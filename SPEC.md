# wav2sum

Класс проекта: всерьёз (личный инструмент на каждый день)
Опасные зоны (здесь руль держу сам): мои записи звонков, транскрипты, история диктовок и выученный словарь; подпись и bundle id приложения (от них зависят разрешения macOS); протокол сокета между демоном и Swift-приложением

## Цель

Krisp + Wispr Flow для macOS с двумя явно выбранными режимами. Local: Qwen3-ASR для диктовки, Gemma для чистки, Qwen или Nemotron 3.5 Transcribe 30B IQ4_NL для звонков без summary. Cloud по явному `--cloud` в CLI или выбору в мастере приложения: Deepgram для распознавания, OpenAI для чистки/summary/глав. Запись звонков автоматическая; обработка ручная по умолчанию, либо после отдельного opt-in автоматически по успешному завершению записи. Русская, английская и смешанная речь. Закрытое распространение друзьям без SaaS/аккаунтов/общих встроенных ключей; внутренний рабочий API не подключаем.

## Критерии готовности

Каждый критерий проверяется тестом, командой или конкретным действием руками.

- [ ] Тесты и линтер проходят — `uv run pytest && uv run ruff check && uv run ruff format --check`, CI зелёный на macOS
- [ ] Звонок записывается сам и останавливается после конца; обработка вручную в TUI/cloud menu-bar Summarize Last Meeting либо по отдельному auto-process opt-in. Local создаёт transcript/meta без summary, cloud также summary/главы; cloud-автоматизация требует отдельного согласия на отправку звонков.
- [ ] Cloud summary опирается только на сказанное; local не вызывает LLM для summary и не создаёт новый `summary.md`.
- [ ] Диктовка: зажать правую ⌥, сказать фразу, отпустить — текст сам вставляется в поле под курсором и остаётся в буфере обмена
- [ ] Исправление термина после вставки запоминается — руками: исправить «гитхаб» → «GitHub», продиктовать снова; `tests/test_vocabulary.py`
- [ ] Local: Qwen распознаёт диктовку; call_model выбирает Qwen (окна до 20 с) или Nemotron (до 50 с). Call ASR загружается отдельно по требованию и освобождается после успеха/ошибки; Nemotron worker закрывается/reap-ится. Cloud: Deepgram для обоих видов аудио. Проверка: tests моделей/кэша и настоящие synthetic local smoke.
- [ ] Звонки и диктовки видны в `wav2sum tui`, обработанные звонки и диктовки удаляются вручную; необработанная запись из TUI не удаляется. История диктовок старше семи суток очищается при запуске daemon и ежечасно; vocabulary, edits и звонки сохраняются. Проверки: `tests/test_history.py`, `tests/test_history_retention.py`, TUI smoke.
- [ ] Q-1: фиксированный на сессию ограниченный контекст терминов передаётся Qwen/Deepgram/Nemotron; подсказка не разрешает выдумывать или принудительно подменять слово. Контекст ASR различается в кэше звонков.
- [ ] Q-2: LLM-чистка сохраняет смысл, факты и языковые вставки, применяет явные самокоррекции без локальных эвристических блокировок. Качество оценивается на примерах; пустой ответ и реальные ошибки не выдаются за успешную чистку.
- [ ] Q-3: cloud-диктовка начинает один HTTP upload во время речи, без повторной отправки PCM и без preview; полный ответ принимается только после последнего чанка и EOF. Local обрабатывает поступающий VAD и ограниченный изменяемый хвост, не распознаёт весь разговор заново. Финализация сохраняет контрольный хвост; отмена, disconnect и shutdown закрывают сессию без вставки позднего результата. Полнота конечной выборки не гарантирует общий WER.
- [ ] Q-4: local-звонки получают связные ограниченные фрагменты, но не смешивают говорящих и не выдают VAD-границы за word timestamps. Произнесённые самокоррекции остаются в транскрипте.
- [ ] Q-5: фактические пункты cloud summary ссылаются на существующие реплики; длинные звонки сводятся в пределах контекста с сохранением источников. Проверка ссылки не доказывает смысловую истинность пункта.
- [ ] Q-6: технические проверки и реальные локальные smoke отделены от пользовательской оценки качества/задержки и live-проверки платных API.
- [ ] Обычный standalone bundle содержит Python/runtime-зависимости/capture/совместимый FFmpeg, не зависит от checkout/venv/Xcode пользователя, не включает скачиваемые ASR/LLM/diarization weights, секреты и историю. Явный private-beta build отдельно включает введённые владельцем friend-ключи; обычная сборка их не обнаруживает и не копирует. Небольшой Silero VAD входит в runtime. Проверка: перенос bundle и isolated-home imports/audio decode. Минимальный macOS берётся из реальных Mach-O, notarization отдельно.
- [ ] Первый запуск не запускает daemon до явного Apply. Settings сохраняет выбранный app mode и модели, управляет Keychain/явными downloads/permission buttons; busy recording/dictation/loading/jobs не прерываются ради переключения.
- [ ] Share Reviewed Examples показывает собственные тексты, Select All Shown не выбирает скрытые, правка target снимает human confirmation, отдельное согласие создаёт новый JSONL без overwrite/network/audio/calls/private metadata и без изменения источников.
- [ ] Профили 16/24/32/48 GiB помечены provisional; M4/Pro/Max не выдаются за измеренные на M5 Max. Runner сохраняет cold/warm repeats/quality/RSS/swap без текста по умолчанию; оценка clean требует отдельного эталона. Ограничения памяти/качества и внешние workload-факторы раскрыты.

## Не делаем

- Не передаём аудио или текст за пределы машины в local. Явный cloud-флаг CLI или согласованный выбор app mode разрешает Deepgram ASR и OpenAI cleanup/summary; ошибки не включают fallback. LoRA-примеры только явно экспортируются в локальный файл с отдельным согласием; приложение не отправляет их на сервер или ноутбук автора.
- Windows и Linux как целевые платформы (только macOS на Apple Silicon)
- Остальные фишки Loom (CHU-103): запись экрана и камеры, ссылки и шаринг, комментарии, аналитику просмотров, голосовые заметки

## Решения

Текущая архитектура (по коду). Карта модулей, публичных функций и типов — в ARCHITECTURE.md:

- **Процессы.** Swift menu bar приложение (`native/app/`) запускает Python-демон (`daemon.py`) и общается с ним по Unix-сокету `~/Library/Application Support/wav2sum/daemon.sock` строками JSON. Команды: `status`, `subscribe`, `dictate_audio` (кусок звука диктовки во время речи, `first` начинает новую), `dictate_cancel` (отменяет поток распознавания на этом соединении при совпадении `session`), `dictate` (с полями `command` и `translate` для режима, `streamed` — в `audio` только хвост после `dictate_audio`, `before` и `after` — до 20 символов поля по обе стороны курсора: по ним `fit_to_cursor` ставит строчную и пробел в начале и убирает точку в конце), `correction`, `record_start`, `record_stop`, `process`, `summarize_last_meeting`, `shutdown`. Summary-last возвращает `{out_dir, already_done:true}` либо стандартную `{job}`; у queued summary-only job `out_dir` уже указывает на существующий transcript. Swift передаёт строковый `session` в кусках, финальном запросе и отмене. Только исходное соединение получает события `{"event":"dictation_preview","session":"…","text":"…"}`; повтор одинакового текста и поздние события завершённого, заменённого или отменённого потока отбрасываются. `{"event":"history_pruned","deleted":N}` содержит только число и заставляет TUI перечитать историю. Клиенты без `session` не запрашивают предварительное распознавание. CLI (`cli.py`) и TUI (`tui.py`) ходят в тот же демон через `client.py`.
- **Dev-watch.** Явный `wav2sum app --watch` управляет только дочерним dev bundle `~/Applications/Wav2Sum.app`, не standalone. Один stage-only сборщик обслуживает обычную установку/bootstrap/watch: неизменяемый снимок Swift приложения и иконки, подписанный отпечаток с именами/границами файлов, прежняя Info.plist для совместимого dev bundle и проверка сертификата/requirement. Native handoff на main thread запрещает новую диктовку и ждёт её запись/финализацию, выделение, insertion probe, исправления и ACK correction/menu/settings; демон, записи и jobs не останавливаются. После ready устанавливается проверенный снимок независимо от следующих editor-save; они идут в следующую сборку. Неуспешная сборка повторяется с растущей задержкой, сохраняя лишь последнюю попытку текущего watcher. При подтверждённом отказе запуска после swap старый bundle восстанавливается; неопределённый результат останавливает watcher без сигналов и повторного обмена, пара bundle сохраняется. После ACK новой версии собственный scratch/старый bundle удаляются; старые до сессии каталоги и ручные installer/bootstrap backups не очищаются. Ctrl-C ждёт диктовку/исправления и закрывает только dev-app для следующего запуска; второй Ctrl-C или прерывание уже начатого exit/swap могут потребовать ручного восстановления. Пользователь не запускает параллельно другой app/installer; защиты от враждебного writer между проверкой и syscall нет. Пассивный запуск daemon запрещён; явные Settings/Turn On сохраняют штатный запуск и прежнюю retention. Нужен совместимый подписанный bootstrap и однократный idle-переход; обычный Quit старого app может штатно остановить daemon.
- **Режим и настройки.** CLI `--cloud` не читается/не пишется в TOML и не включается наличием ключей. Native first-run/settings через `wav2sum setup` (JSON stdin/stdout) сохраняет явный выбор в app-settings.json. `configure` RPC валидирует согласия, под recording lock запрещает смену при recorder/streams/loading/queued/running jobs, атомарно сохраняет preferences и останавливает idle daemon при смене mode/model; auto-process-only обновляется live. Native ждёт старый socket, затем запускает выбранный режим; force-kill/fallback нет. Клиентский cloud проверяется до ASR/process/summary-last/subscribe; mismatch — ошибка. CLI fallback только при недоступном socket, не отказе запроса. Конфликт app `--cloud` с сохранённым local открывает выбор, не игнорируется молча.
- **Cloud-ключи.** CLI cloud-keys и Save Cloud Keys сохраняют прежний Keychain service/accounts, add/update без удаления ACL; secure fields передают секреты только по stdin pipe в памяти. Обычный bundle без ключей. Явный `distribution --private-beta` получает оба выделенных friend-ключа скрыто в terminal, не из argv/env/Keychain, и включает resource только в новый signed artifact; его извлекаемость и приватная раздача согласованы владельцем. Runtime: env → собственный Keychain → beta resource → ошибка; отказ Keychain не обходится. Beta resource не импортируется автоматически в Keychain. Passive status сообщает только presence; Local не читает ключи. Режим и cloud/auto-upload consent остаются явными; новые ключи приложение не создаёт.
- **Модели в памяти.** Local preload — Qwen/VAD/Gemma диктовки; отдельный call_session выбирает call_model и освобождает его в finally, включая reap Nemotron worker, cache hit не загружает call ASR. Ни Qwen, ни Gemma не скачиваются при обычном старте: setup готовит pinned snapshots явно. Подготовленный pyannote работает локально без токена, telemetry выключена; первоначальный gated access — отдельное принятие terms и токен только на подготовку. Cloud warm-up проверяет ключи без paid-запросов. Ошибка подготовки видна в app; после исправления Apply перезапускает idle failed daemon.
- **Звонки.** По умолчанию остановка только сохраняет запись. Auto-process выключен, local opt-in ставит завершённую запись в обычную очередь без summary; cloud opt-in отдельно подтверждает автоматические transfers/charges. Capture error не ставится в очередь, startup старые записи не обрабатывает. Сохраняются guards активной/дублированной/неоднозначной/partial записи. Local: echo → VAD/pyannote → Qwen-окна до 20 с или Nemotron до 50 с, без пересечения спикеров/выдуманных word timestamps. Cloud — Deepgram utterances/diarize и grounded summary/главы. Cache различает backend и terms; transcript/meta/правила удаления звонков не мигрируются.
- **Последняя встреча из меню.** Summarize Last Meeting доступна ready/cloud вне записи, in-flight guard исключает повторный UI request. Только собственный completed call по started_at (fallback audio chronology), не mtime output; unfinished sidecar/ambiguous/partial output отказываются. Готовый summary открывается, активная job переиспользуется, raw идёт обычным pipeline, transcript — summary-only без ASR. Атомарно добавляется только summary.md, исходные audio/transcript/meta сохраняются. Новое завершение уведомляет без принудительного открытия; auto-process — независимый явный opt-in.
- **Экспорт примеров.** sharing.py читает history/edits под прежними locks и даёт content-stable ids, только текстовые поля. GUI фильтрует и выбирает все показанные, подтверждает target отдельно, снимает подтверждение после правки. Export повторно разрешает выбранные ids по текущим источникам, требует training consent/human-confirmed target и публикует новый private JSONL атомарно без overwrite. Исключены timestamps/app/title/paths/audio/calls; network send/бессрочного внутреннего архива нет. Уже экспортированный файл не входит в seven-day retention.
- **Распространение.** distribution.py собирает только в новый отдельный output, включает relocatable uv CPython/RECORD runtime dependencies и заранее скомпилированные Swift helpers; native запускает bundled Python напрямую, не login shell. FFmpeg 8.1.3 из проверенного исходника LGPL-only без внешних codec libs/network; совместимые TorchCodec ABI и build-rpaths исправляются в копиях, system FFmpeg не меняется. Source/license/rebuild manifest внутри artifact; обязательны license review и отдельная Developer ID/notarization перед публичной раздачей. Bundle id/существующий способ подписи не меняются, рабочего app deployment нет.
- **Диктовка.** Закреплённый Qwen (`bcd2b5b7f32b480ab5790554cfa8347f246a14f3`) и Gemma local; Nova-3 и `gpt-6-luna` с `service_tier=fast` cloud. Cloud-summary по умолчанию `gpt-6.1-terra`, без явного Fast. Обе OpenAI-модели через Chat Completions с `reasoning_effort=none`. Swift шлёт демону PCM каждые 1 с local / 250 мс cloud, в первом запросе также `app`/`title`; при отпускании отправляет весь ещё не отправленный хвост. Cloud с первым непустым PCM начинает один HTTP/1.1 chunked upload raw linear16/16 кГц/mono, передаёт собственные PCM-копии во время речи и посылает EOF только после последнего чанка. Полный HTTP response — единственный финал; живого текстового preview и повторного ASR нет. Это перекрывает setup/upload со временем речи, но не доказывает момент начала provider inference; явной vendor-гарантии chunked buffering в найденной документации нет. Ограниченный backlog не теряет чанки: переполнение завершает сессию ошибкой; один заранее готовый крупный аудиовход остаётся допустим. Finish ждёт не более 20 с после закрытия входа, успешный результат кэшируется; конкурентный finish не удваивает запрос. Сетевой timeout HTTP звонков остаётся 300 с. Local обрабатывает только новые Silero-окна по 512 сэмплов, кэширует законченные спаны и распознаёт ограниченный активный хвост без полного аудиобуфера; preview не становится финалом. Local HUD — 320×80, стартует справа снизу, перетаскивается без активации, сохраняет позицию в процессе и ограничивается видимой областью экрана. Cloud HUD — 190×40 по центру снизу, пропускает клики и не показывает preview. Клик по самому Local HUD не инвалидирует цель вставки; остальные проверки фокуса/поля/курсора прежние. `auto` выбирает язык чистки по готовому тексту, явный `ru`/`en` сохраняется.
- **Контекст и чистка.** `DictationContext` фиксирует стиль, язык, snippets, явные термины и выученные исправления при первом чанке. `recognition_terms` возвращает до 50 уникальных подсказок в пределах 500 UTF-8 байт, без управляющих символов. Qwen получает contextual prompt, Deepgram повторные `keyterm`, Nemotron worker `prompt`. LLM получает исходную расшифровку со snippet-маркерами, без regex-подготовки самокоррекций, и отвечает один раз. Семантических постпроверок отрицаний/чисел/имён/сокращений/роста нет; непустой успешный ответ принимается, а пустой ответ или настоящая ошибка сохраняют сырой текст. Явные snippets, словарь, стиль и подгонка к курсору остаются. Перевод/команды имеют отдельные контракты; ошибка перевода не вставляет непереведённое.
- **Узкие исправления ASR.** Смешанное Cyrillic/Latin написание приводится к заданному термину только при точной транслитерации (`Немotron` → `Nemotron`), без fuzzy-подстановки созвучных имён и без записи выученного исправления. Это отдельная нормализация ASR, не эвристический валидатор LLM-чистки.
- **Язык cloud-ASR.** Auto использует Nova-3 `language=multi` с повторяемым `language_hint=ru&language_hint=en` в HTTP. Это штатное смещение распознавания к языкам проекта, не whitelist и не гарантия точности. Явные ru/en передаются как фиксированный язык без hint. Выбор языка LLM-чистки по готовому тексту не восстанавливает неверно распознанную речь.
- **Отмена и финализация.** Финальный запрос захватывает исходную сессию в порядке чтения сокета до запуска фоновой обработки, включая клиентов без `session`. Чтение следующих запросов не блокируется LLM. Esc, замена сессии, disconnect и shutdown закрывают транспорт; отменённый результат не вставляется и не добавляется в историю. Cloud close будит ожидающий finish, очищает backlog и делает best-effort shutdown активного socket без ожидания сети; уже начатые DNS/connect могут завершиться позже. Уже начатый локальный inference/LLM также может доработать, но результат отбрасывается. Неоднозначно отправленный POST не повторяется. Существующие ограничения AX/фокуса сохраняются.
- **OpenAI transport/lifetime.** На один OpenAILLM — одно direct HTTP/1.1 соединение и lock; TLS проверяется штатно, configured proxy остаётся на прежнем urllib без pooling и без прямого preconnect. Startup warm-up только проверяет ключи, без paid-запросов. При непустом cloud audio и включённой cleanup `preconnect` в фоне готовит TCP/TLS без HTTP, ключей или текста; продолжающееся аудио проверяет готовность и обновляет обнаруженный закрытый socket, таймера переподключений в простое нет. Один warming worker на клиента, connect вне transport lock; foreground POST не ждёт warming и при miss/failure идёт обычным путём. Закрытый peer отбрасывается перед отправкой, если обнаружен; после неоднозначной сетевой ошибки POST не повторяется автоматически. `unload` закрывает transport, generation invalidates pending connect; поздний socket не заменяет активный и не восстанавливает закрытый клиент. DNS/connect cancellation best-effort. Daemon ждёт in-flight model work перед закрытием dictation/summary, CLI/factcheck закрывают своих клиентов в finally. Отмена сохраняет CancelledError даже при ошибке завершающейся фоновой работы.
- **Источники summary.** Cloud summary получает таймкодированный транскрипт; фактические строки содержат проверенные `[U1 00:01–00:04]`. Проверяются существование и видимость ссылок в текущей части/заметках; скрытая или вымышленная ссылка не принимается. Длинная монореплика делится с тем же настоящим ID/диапазоном, сведение заметок ограничено контекстом. Проверка ID не доказывает смысловую поддержку утверждения. `factcheck` не считает ссылки новыми числами/именами. Главы по-прежнему отдельным вызовом.
- **Замеры.** В прежнем `timings` дополнительно сохраняются `preview` (с первого полученного аудио; local и исторический cloud WS), `finalize` (с финального запроса до готовности, включая ожидание текущего local preview), cloud `audio_sent`/`audio_received` в секундах; после успешного HTTP запроса `audio_sent` — длительность полного переданного аудио, не provider acknowledgement каждого чанка или биллинг. `asr_live` — только накопленная local-работа во время речи. `latency` читает историю и показывает отдельные local/cloud p50/p95 и отношение отправленного/полученного аудио; старые WS/batch-записи остаются в cloud-агрегатах, поэтому это не baseline текущего upload. Swift пишет release→callback и отдельный insertion probe в `app.log`: monotonic время от event-tap release до ready/send и интервал до точного AX-совпадения исходного поля с заменённым UTF-16 selection. Проверки раз в 25 мс не дольше 2 с после paste send; нижняя/верхняя граница показывают фактическую неопределённость, не обещают ошибку ≤25 мс. Нет текста/selection AX, прежнее значение или timeout — unavailable/unconfirmed, не успех; clipboard-only не измеряется. Текст поля probe не логирует, формат истории/протокол не меняет. Это подтверждение AX-значения, не screen paint, физический контакт клавиши или расчёт биллинга.
- **Ограничение языка Nemotron.** Проверенный worker 0.9.4 принимает и проверяет `language`, но модель не использует его для ограничения распознавания. В local-звонках явный язык задаёт язык результата, а не гарантированную фильтрацию речи; Qwen и Deepgram поддерживают принудительный язык.
- **Хранилище.** Конфиг `~/.config/wav2sum/config.toml` (`config.py`), история диктовок `dictations.jsonl`, словарь `vocabulary.json` и примеры правок `edits.jsonl` в `~/Library/Application Support/wav2sum/`. Согласованная fixed retention: строго старше 7×24 часов в UTC удаляется из dictations.jsonl при запуске daemon и далее ежечасно в фоновом worker, не через dictation handler. Это необратимое удаление строк, не Корзина; применяется и к ранее накопленной истории. Ровно cutoff, будущие, неизвестные и timezone-naive даты сохраняются. Общий lock с append/delete, atomic replace и сохранение retained bytes/order/mode; malformed JSON/UTF8 и write failures не меняют оригинал. Symlink/hardlink/non-regular history отклоняются. Vocabulary, edits и все данные звонков retention не затрагивает. Ручное удаление звонков через history.py сохраняет прежнюю политику Корзины/доступного fallback.

### Куда двигают архитектуру задачи из Linear

- **ASR на Neural Engine (CHU-97 → 98, 99, 100, 101, 102).** Закрыт по итогу бенчмарка CHU-99, архитектура не меняется: GigaAM остаётся на MPS. Конвертация (CHU-98): `coreml.py` (`uv run --group coreml python -m wav2sum.coreml`) собирает multifunction `.mlpackage` с фиксированными формами 5/10/20 с (`EnumeratedShapes` уводит всю модель на CPU), attention без SDPA (на ANE SDPA пропускает паддинг сквозь bool-маску). Бенчмарк на M5 Max: WER ANE в пределах 0.2 п.п. от MPS (golos, fleurs, minds14); ASR диктовки 3–5 с 10–13 мс против 23–26 мс, от 8 с ANE не быстрее, на 15 с вдвое медленнее; во время summary Gemma 12B p90 диктовки 16 мс против 143 мс; созвон 35 мин — вдвое меньше энергии (≈ 60 Дж против 125 Дж), но медленнее (7.6 против 5.6 с). Выигрыш — десятки мс на фоне LLM-чистки в сотни мс, а цена — второй бэкенд, 422 МБ и 4–8 с загрузки. Если вернёмся: Core ML держит последний вход каждой функции после `predict`, и освобождённый numpy-массив портит кучу (segfault в случайном месте torch через ~100 вызовов), так что вход каждой функции надо хранить до следующего вызова.
- **Lock на модель (CHU-101).** Сделано. У каждой модели в `Models` свой lock, у ленивой загрузки `_load` свой lock на имя модели, так что диктовка не ждёт диаризацию звонка и первую загрузку pyannote, а ждёт только ту же модель между батчами звонка. GigaAM и pyannote теперь могут идти на MPS одновременно из двух потоков. LLM остаётся в своём потоке `llm`.
- **Ollama → mlx-lm (CHU-107).** Сделано. `llm.py` грузит модель через mlx-lm в процесс демона (или CLI) при первом `chat` и выгружает после `keep_alive` секунд простоя (диктовка 600, summary 60, если модели разные). Все генерации идут в одном потоке `llm` (MLX-потоки привязаны к треду, GPU один). Диктовка (вызов с `timeout`) обгоняет summary: summary идёт через `stream_generate` и между кусками prefill и токенами выполняет ждущие диктовки (CHU-121). Диктовка, прождавшая дольше `timeout`, отменяется и отдаёт сырой текст. Модели с одинаковым именем делят веса. `status` отдаёт `llm_memory_mb` из размера весов и вычитает его из `memory_mb`.
- **Кэш префикса промпта диктовки (CHU-119).** `LLM` диктовки (`cache_prefix=True`) держит KV-кэш всего, кроме последнего сообщения (системный промпт со стилем и словарём, примеры): до 4 префиксов на модель, ключ — их токены, генерация идёт на копии. Кэш выгружается вместе с весами и входит в `llm_memory_mb`. Summary без кэша.
- **Prompt lookup в чистке (CHU-120).** `Dictator.clean` зовёт `chat(..., lookup=True)`: черновик ответа берётся из промпта (токены после последнего совпадения 3, 2 или 1 последних токенов ответа), модель проверяет 4 токена за проход и оставляет те, что выбрала бы сама. Кэш для этого обрезаемый (`KVCache` вместо `RotatingKVCache` в слоях окна), в том числе кэш префикса. Перевод, команда и summary идут через обычный `stream_generate`. Бенчмарк на Mac: чистка в 1.4–1.6 раза быстрее.
- **Длина summary в токенах (CHU-124).** `summarizer.py` считает токены токенайзером модели (`LLM.count_tokens`, в потоке `llm`) и режет длинный транскрипт по токенам. `num_ctx` по умолчанию 32768: у Gemma 4 12B 40 из 48 слоёв со скользящим окном 1024, поэтому 32k промпта стоят около 370 МБ сверх 8k (замер на Mac 48 ГБ). В mlx-lm окно не фиксировано, `num_ctx` задаёт только порог нарезки и `max_tokens` ответа.
- **Автовставка после диктовки (CHU-104).** Только Swift: в `Dictation.swift` уже есть `Keyboard.press` и `Clipboard.save/restore`, то есть ⌘V и возврат буфера. Протокол демона не меняется. Проверить, что обучение на правках (`correction`) работает со вставкой так же.
- **Перевод на английский сразу (CHU-96).** ⌃ + клавиша диктовки (и в hands-free). Swift шлёт `translate: true` в команде `dictate`, демон передаёт его в `Dictator.dictate`; русская речь идёт через `TRANSLATE_PROMPT` с английским стилем приложения, английская — через обычную очистку. Если LLM упала или выдала мусор, ничего не вставляется, приложение пищит. Перевод не учит словарь на правках. В истории у записи есть поле `translate`, TUI показывает режим `translate`.
- **Главы в summary (CHU-103).** Из фишек Loom взяли главы. Теперь cloud summary использует таймкоды и ссылки на источники; главы остаются отдельным вызовом `summarizer.chapters` без thinking по транскрипту с таймкодами, с `max_growth`; длинный звонок идёт по частям. Остаются только строки «- мм:сс — тема», чей таймкод не дальше 5 с от начала реплики (время подтягивается к нему: модель пишет 00:00 вместо 00:01), и они дописываются в `summary.md` разделом «Главы». Модель не держит лимит в 8 глав (на звонке 31 мин давала 14–16), а длинный звонок даёт до 8 с каждой части, поэтому больше 8 строк сливаются ещё одним вызовом без thinking. Почему отдельно: с таймкодами и разделом глав в промпте summary Gemma 12B с thinking зацикливалась на перепроверках до лимита токенов (звонок 31 мин, дважды, 438 и 856 с), и в `summary.md` попадали мысли.
- **Прогрев LLM диктовки (CHU-128).** LLM диктовки выгружается через 10 минут простоя. Первый `dictate_audio` с `first` при выгруженной модели запускает в фоне `Dictator.warm_llm` (тот же короткий вызов чистки, что при старте демона: веса и кэш префикса стиля `default`), один на раз; к отпусканию клавиши модель уже в памяти. Протокол и время жизни модели не меняются.
- **Первое слово диктовки (CHU-129).** Замер в `app.log` (`microphone first buffer/sound after N ms`): AirPods отдают звук через 0,3 с после нажатия, а в 2 из 5 — через 0,8 с (до этого нули), встроенный микрофон — через 0,19 с. Поэтому, если вход по умолчанию — Bluetooth, `Microphone` пишет диктовку со встроенного микрофона Mac (как Wispr Flow); нет встроенного — пишет с входа по умолчанию. Запись звонков не меняется.
- **Вычитание эха (CHU-142).** Для звонков через колонки: `echo.py` сначала вычитает эхо из канала микрофона адаптивным фильтром (NLMS в частотной области, блок 20 мс, хвост 240 мс) с системным каналом как опорой, сдвинутым на оценку задержки. Фильтр учится только в кадрах, где в микрофоне одно эхо, поэтому своя речь поверх собеседника его не сбивает и не вычитается. Гейтинг этих кадров остаётся для остатка. Синтетика: эхо под своей речью падает на ~40 дБ; около 35 с на час звонка на CPU.
- **Поиск в TUI (CHU-127).** `/` открывает строку поиска: списки звонков и диктовок фильтруются по подстроке без учёта регистра (звонок — имя, `summary.md`, `transcript.txt`; диктовка — текст и распознанное). Файлы читаются на каждый фильтр, без индекса и моделей. Esc сбрасывает.
- **Набор фраз для замера диктовки (CHU-138).** `evalset.py`: 46 фраз с эталоном и терминами (русский, английский, смешанные). Андрей начитывает их один раз в четырёх условиях (`quiet`, `airpods`, `noise`, `whisper`) в `~/wav2sum/evalset/<условие>/NN.wav` через ffmpeg с входа по умолчанию; в репо записи не кладём. Замер только читает: VAD → ASR (`Dictator.recognize`) и чистка (`Dictator.clean`, стиль `default`) отдельно, WER по корпусу (нижний регистр, ё → е, без пунктуации) и доля терминов, написанных как в эталоне. Перед каждой чисткой `mx.random.seed(0)`, чтобы повтор дал те же числа. Новые фразы — только в конец: номер фразы и есть имя файла.
- **Шумодав Apple для диктовки (CHU-143).** Не включаем. Voice Processing (`setVoiceProcessingEnabled`) работает только на живом микрофоне, поэтому для A/B `evalset record --vp` пишет фразы Swift-рекордером `native/vprecord.swift`. VP вырезает весь звук, который играет сам Mac (как эхо), так что шум для замера должен идти с другого устройства. Замер: шум с телефона, 46 фраз, WER asr 15.8 % без VP и 17.2 % с ним (7 ошибок из одной фразы, где AGC догонял начало), чистка 10.2 % против 9.9 %, термины после чистки 29/42 против 32/42, то есть в пределах разброса. Шум VP убирает (пол ниже на 7 дБ, речь громче на 8.5 дБ), но модели при SNR ~17 дБ и так справляются, а VP даёт первый звук через ~1 с после старта и упирает пики в 0 дБ.
- **Примеры чистки из своих правок (CHU-140).** На `correction` демон находит в истории диктовку с тем же `text` и дописывает строку в `edits.jsonl` рядом с историей (`raw`, `text`, `edited`, стиль, язык); `dictations.jsonl`, словарь и протокол не меняются. При старте демона (и в `evalset`) `user_examples` берёт по 3 последних правки на стиль и язык как пары «raw → edited» для few-shot чистки; правка длиннее порога чистки (`MAX_GROWTH`) считается переписыванием и не берётся. Нет правок — статичные примеры. Набор не меняется до перезапуска, чтобы кэш префикса попадал. С `learn = false` правки не пишутся.
- **Проверка фактов в summary (CHU-135).** `factcheck.py` (`uv run python -m wav2sum.factcheck [папка звонка ...]`, по умолчанию 3 последних звонка) только читает: заново считает summary по `transcript.txt` (модель, `num_ctx` и термины как в `calls.py`, язык из `meta.json`, summary на языке звонка) и показывает строки summary с числами и именами, которых нет в транскрипте. Число ищется среди чисел транскрипта без таймкодов (50,000 = 50 000), имя — слово с заглавной не в начале предложения или с заглавной внутри (DeepSeek, GPU), без учёта регистра, кириллица по основе. Числа словами в транскрипте («hundred thousand») не распознаются и попадают в отчёт; перепутанную связь при двух верных фактах проверка не ловит. Запускать при смене промпта или модели summary.
- **Шаблон summary под встречу (CHU-141).** Один промпт на все встречи: «Тема» и «Обсуждения» всегда, разделы «Решения», «Задачи», «Открытые вопросы» только с содержимым (без «Не обсуждалось» и «Нет»), и раздел под суть встречи со своим названием (советы преподавателя на уроке, впечатления на интервью, обратная связь на 1:1). Заметки по частям длинного звонка собирают и советы. Проверка `factcheck` на звонках 20.10 (урок) и 26.10: совет про гласные в summary урока, пустых разделов нет. Отдельный вызов LLM для выбора типа встречи не делали.
- **Язык по каналу звонка (CHU-134).** В `call`-раскладке при `auto` язык определяется отдельно для микрофона (после вычитания эха) и для системного канала, и каждый канал распознаётся своей моделью. Язык звонка (summary, `meta.json`) — язык моего канала, а если я молчал — собеседника. `CACHE_VERSION` 7.
- **Собеседники в автозаписи (CHU-132).** Демон передаёт в `process` `Speakers(None, 2, 7)`: на системном канале pyannote ищет от 1 до 6 человек. В `diarizer.py` у кластеризации VBx `Fb` 2.0 вместо 0.8: с 0.8 звонок 20.10 (1:1) давал второго собеседника из коротких «okay», «mm» (18 с из 652 с). Порог AHC (0.6–1.0) на это не влияет. Проверка на Mac: 20.10 и 26.10 — по одному собеседнику; смесь их системных каналов кусками по 3 мин — двое (1–3 % речи не тому), плюс 2 мин моего голоса — трое. pyannote на MPS — около 30 с на 30 мин звонка. Если в диапазоне нашёлся один человек, он остаётся просто «Собеседник» (имя из `them`), без номера; явно заданное имя через `--speaker` имеет приоритет. `CACHE_VERSION` 9.
- **CI и Dependabot (CHU-106)** идут отдельным треком и архитектуру не трогают.
