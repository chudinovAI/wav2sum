# wav2sum

Класс проекта: всерьёз (личный инструмент на каждый день)
Опасные зоны (здесь руль держу сам): мои записи звонков, транскрипты, история диктовок и выученный словарь; подпись и bundle id приложения (от них зависят разрешения macOS); протокол сокета между демоном и Swift-приложением

## Цель

Локальный аналог Krisp + Wispr Flow для macOS. Звонки в Zoom, Teams и Webex записываются сами, после звонка появляются транскрипт с метками говорящих и краткое содержание. Диктовка по правой ⌥ превращает речь в чистый текст в буфере обмена в любом приложении. Всё работает на своём компьютере, на русском и английском.

## Критерии готовности

Каждый критерий проверяется тестом, командой или конкретным действием руками.

- [ ] Тесты и линтер проходят — `uv run pytest && uv run ruff check && uv run ruff format --check`, CI зелёный на macOS
- [ ] Звонок в Zoom записывается сам и останавливается после конца — руками: созвон на 1 минуту, в `~/wav2sum/output/call-*/` появились `transcript.txt` и `summary.md`
- [ ] Summary опирается только на сказанное — руками: прочитать `summary.md` после звонка, в нём нет выдуманных фактов
- [ ] Диктовка: зажать правую ⌥, сказать фразу, отпустить — текст сам вставляется в поле под курсором и остаётся в буфере обмена
- [ ] Исправление термина после вставки запоминается — руками: исправить «гитхаб» → «GitHub», продиктовать снова; `tests/test_vocabulary.py`
- [ ] Английская речь распознаётся Parakeet, русская GigaAM — руками на двух записях; `tests/test_dictation.py`
- [ ] Звонки и диктовки видны и удаляются в `wav2sum tui` — руками: `x` на звонке, папка ушла в Корзину; `tests/test_history.py`

## Решения

Текущая архитектура (по коду):

- **Процессы.** Swift menu bar приложение (`native/app/`) запускает Python-демон (`daemon.py`) и общается с ним по Unix-сокету `~/Library/Application Support/wav2sum/daemon.sock` строками JSON. Команды: `status`, `subscribe`, `dictate`, `correction`, `record_start`, `record_stop`, `process`, `shutdown`. CLI (`cli.py`) и TUI (`tui.py`) ходят в тот же демон через `client.py`.
- **Модели в памяти.** `models.py` держит ASR, VAD, диаризацию и определение языка; демон грузит их один раз и переиспользует для звонков и диктовки.
- **Звонки.** `autorecord.py` смотрит, какое приложение держит микрофон, `capture.py` пишет WAV через Swift-хелпер (`native/capture.swift`): микрофон и системный звук отдельными каналами. `calls.py`: подавление эха (`echo.py`) → VAD → диаризация → язык → ASR → сборка реплик (`conversation.py`) → summary (`summarizer.py` через `llm.py`/Ollama). Результат в `~/wav2sum/output/<call>/`: `transcript.txt`, `summary.md`, `meta.json`.
- **Диктовка.** Swift-приложение пишет звук по ⌥ и шлёт его демону; `dictation.py` распознаёт, чистит текст LLM в стиле под текущее приложение, раскрывает сниппеты; Swift кладёт текст в буфер обмена и вставляет его ⌘V, если приложение под фокусом не сменилось. `vocabulary.py` учится на правках после вставки.
- **Хранилище.** Конфиг `~/.config/wav2sum/config.toml` (`config.py`), история диктовок и словарь в `~/Library/Application Support/wav2sum/`, удаление через `history.py` (в Корзину).

### Куда двигают архитектуру задачи из Linear

- **ASR на Neural Engine (CHU-97 → 98, 99, 100, 101, 102).** У `Transcriber` появляется второй бэкенд (Core ML рядом с MPS) и опция `asr_backend`, `.mlpackage` ложится в `~/Library/Application Support/wav2sum/`. Всё решает бенчмарк CHU-99: если WER хуже, эпик закрываем, и архитектура не меняется.
- **Один lock на все модели (CHU-101).** Сейчас `Models` держит один `threading.Lock`, и диктовка ждёт диаризацию созвона. Делим lock по вычислителю (ANE, GPU, CPU). Имеет смысл только после CHU-100.
- **Ollama → mlx-lm (CHU-107).** Шов один: класс `LLM` в `llm.py` (`chat`, `unload`), его создают три места (`cli.py`, `daemon.py`, `dictation.py`). Но LLM переезжает внутрь процесса демона: память модели, `keep_alive`, `_llm_memory_mb` и делёж GPU с ASR теперь наша забота, а не Ollama. Это пересекается с CHU-97 и CHU-101, поэтому решить до них.
- **Автовставка после диктовки (CHU-104).** Только Swift: в `Dictation.swift` уже есть `Keyboard.press` и `Clipboard.save/restore`, то есть ⌘V и возврат буфера. Протокол демона не меняется. Проверить, что обучение на правках (`correction`) работает со вставкой так же.
- **Перевод на английский сразу (CHU-96).** Новый хоткей в Swift, как у правки голосом (⇧ + ⌥), и новый промпт в `dictation.py`. Если режим передаётся в команде `dictate`, протокол меняется с двух сторон.
- **CI и Dependabot (CHU-106)** идут отдельным треком и архитектуру не трогают.
