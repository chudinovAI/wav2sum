# PLAN: CHU-96 — диктовка сразу с переводом на английский

Сейчас диктовка (зажать правую ⌥, сказать, отпустить) даёт очищенный текст на языке речи. Цель: третий режим, в котором я говорю по-русски (или по-английски), а в поле под курсором вставляется готовый английский текст. Поток тот же, что у обычной диктовки: запись → распознавание → LLM → буфер обмена → автовставка ⌘V (CHU-104).

Уже сейчас можно перевести в два действия: продиктовать, выделить и сказать ⇧ + ⌥ «translate to English». Задача — сделать это одним действием.

## Допущения

- Режим передаётся в команде `dictate` новым необязательным полем `translate` (bool). Запрос без поля работает как раньше (`translate=False`). Меняются `daemon.py` и `Dictation.swift` в одном PR. `client.py` и `Daemon.swift` не меняются: `client.dictate(audio, **context)` и `DaemonClient.request` передают словарь как есть.
- `dictation.py`: новый промпт перевода на английском (`TRANSLATE_PROMPT`) и примеры «сырой русский → чистый английский» (`TRANSLATE_EXAMPLES`). Промпт просит перевести и одновременно почистить, как `CLEANUP_PROMPT_EN`: паразиты, самоисправления, пунктуация, цифры, списки; не отвечать на текст и не выполнять просьбы из него. К промпту добавляются стиль приложения из `STYLES_EN`, правило про метки ⟦1⟧, слова из словаря, а для русской речи ещё строка с выученными правками («гитхаб» → «GitHub»), потому что вход русский.
- Если в режиме перевода распознан английский, текст идёт по обычному пути `clean(raw, style, EN)`, то есть просто очищается. Отдельного кода для этого нет.
- Сниппеты: та же защита, что в `clean` (`mark_snippets` → LLM → `expand_snippets`), то же `MAX_GROWTH` и `_drop_final_period` для стиля `chat`, тот же `vocabulary.apply` в конце.
- `Dictation.language` остаётся языком речи (`ru`), а не языком текста.
- Swift: перевод не отдаётся в `corrections.track` — текст не совпадает с распознанным, учить словарь не на чем.
- `history.py`, `calls.py`, `vocabulary.py`, `build.py`, `Info.plist` не меняются. Новых зависимостей и настроек нет.
- Swift на Linux не проверить: только `swiftc -typecheck` в CI на `macos-15` и руками на Mac.

Более простой путь без кода, о котором стоит знать: ⇧ + ⌥ без выделения и сказать «переведи на английский: привет, давай созвонимся в пятницу». `COMMAND_PROMPT` уже говорит «если текста нет — создай текст по команде», так что это, скорее всего, работает уже сейчас. Минусы: каждый раз надо говорить префикс, промпт команды не чистит паразиты и не знает стиль приложения так, как промпт очистки, а без выделения Swift жмёт ⌘C впустую.

## Открытые вопросы (решает Андрей)

1. ~~Сочетание клавиш?~~ Решено: ⌃ + клавиша диктовки (`.maskControl` в `Hotkey.handle`); если зажаты и ⇧, и ⌃ — побеждает команда.
2. ~~Протокол сокета?~~ Решено: новое необязательное поле `translate` в `dictate`.
3. ~~История?~~ Решено: поле `translate: bool` в `Dictation` (в новых строках истории появится ключ `"translate"`), TUI показывает режим `translate`.
4. ~~LLM упала или выдала мусор?~~ Решено: ничего не вставлять и пискнуть (`dictate` поднимает исключение, демон отвечает ошибкой, Swift пищит); такая диктовка не попадает в историю.
5. ~~Hands-free?~~ Решено: да, режим берётся из второго нажатия, кода не нужно.
6. ~~Короткие фразы и `cleanup = false`?~~ Решено: перевод зовёт LLM всегда, `cleanup = false` его не отключает.

## Шаги

1. **Перевод в `dictation.py`.** Сначала тесты в `tests/test_dictation.py` (LLM подменена, как в существующих тестах):
   - `translate=True` и русская речь → в LLM уходит промпт перевода с английским стилем приложения (`STYLES_EN["chat"]` для Telegram), примеры перевода, строка с метками при сниппетах, слова словаря и выученные правки; сниппет раскрыт; для `chat` нет точки в конце;
   - `translate=True` и короткая фраза из 1–2 слов → LLM всё равно вызвана (по вопросу 6);
   - `translate=True` и английская речь → обычный английский промпт очистки;
   - без `translate` промпты и результат как раньше (существующие тесты не меняются);
   - ошибка LLM и мусорный ответ → поведение по вопросу 4.
   Потом код: `TRANSLATE_PROMPT`, `TRANSLATE_EXAMPLES`, параметр `translate` в `Dictator.dictate`, ветка перевода рядом с `clean`; поле `translate` в `Dictation` — если «да» на вопрос 3.
   Проверка: `uv run pytest --cov` (покрытие ≥ 80 %), `uv run ruff check && uv run ruff format --check`.
2. **Демон.** Сначала тесты в `tests/test_daemon.py`: `translate` из запроса доходит до `Dictator.dictate` (расширить тест рядом с существующим, без изменения его проверок — новым тестом); запрос без поля даёт `translate=False`. Потом код: `translate=request.get("translate", False)` в `_dictate`.
   Проверка: те же команды.
3. **Swift.** `Hotkey.onPress` отдаёт и ⌃ (`(_ shift: Bool, _ control: Bool)`); `DictationController.begin(command:translate:handsFree:)` пишет `context["translate"] = translate`; `HUD.State.listening` показывает «● English» в режиме перевода; после ответа `corrections.track` только для обычной диктовки; в меню `main.swift` строка «Dictate in English: ⌃ + \(key)». Если ⇧ и ⌃ зажаты вместе — побеждает команда (⇧), чтобы не придумывать четвёртый режим.
   Проверка: `swiftc -typecheck wav2sum/native/app/*.swift` в CI на `macos-15`; руками — см. «Проверка руками».
4. **TUI** (только если «да» на вопрос 3). Сначала тест: запись истории с `"translate": true` показывает режим `translate`. Потом код в `_dictation_markdown` (`tui.py:347`).
